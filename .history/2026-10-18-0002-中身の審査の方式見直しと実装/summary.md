# 中身の審査を方針の差し込み方式に作り直し、宛先の許可リストとプログラムの実行の審査を実装した

## 概要
送信するファイルの中身の審査を、ゲートウェイがツールコールを差し替える方式から「要求に方針を足してモデル自身に読ませる」方式に作り直し、宛先の許可リストと、名指しのプログラムの実行・作成・設置の審査を足して、実装・試験・docs 反映・push まで終えた（ブランチ `feature/isolated-content-read`、`0471fa6`。main への取り込みが残り）。

## やったこと

- **方式の見直し（2026-10-17 前半）**: 差し替え方式の 2 件の問題（Claude Code の自動モードが差し込みを拒否、`cd … && curl` で止まる）の根本原因が「ゲートウェイが行動を書いてエージェントに実行させること」だと整理し、ゼロベースで 6 案を比べて、方針の差し込み（A）と宛先の許可リスト（E）を採用。要件は `.history/2026-10-17-中身の審査の方式見直しと宛先の許可リスト/変更要件.md`。

## 決定事項

- 方針の差し込み（A）のみ採用し、差し替え方式（F）は残さない。協力は証拠を出させるためだけ、判定は機械的な検証と審査官の判定だけ。
- 許可リスト: 既定 `private`、無い宛先と `unknown` は中身に関係なく止める、CIDR とホスト名の末尾一致、名前解決なし、審査官が宛先を抜き出しゲートウェイが照合、対象は外へ送る操作すべて。
- プログラムの実行: 名指しのスクリプトは無条件に直前の読み取り（触ったか条件は設けない）、環境変数は名前を指定して `printenv`、ファイル数の既定 5、パスの直接実行は読めなければ生成物、読めない実体は作る時点で元を読み実行は通す、木のツールは通す（慣習ファイルの扱いは設けない）、特定できない・読めない入力・読めない中身の書き出し・木の外は止める。
- 設計書に見積もりと段階的な実装の手順を書かない（CLAUDE.md に追記）。
- 「検討して」は説明だけ。決まったら要件・仕様・設計 → 実装 → 試験が全部通るまで直す → docs 反映 → コミット・push。
