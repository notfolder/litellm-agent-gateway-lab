## 概要
aws-ec2 の残りの不具合・試験・機能をプルリクエスト #9 で仕上げ、AWS（amd64、足す台あり、managed と provided）で全部確かめてマージした。

## やったこと
- 2026-11-08 朝の残りの試験（復元は合格、Traefik の更新が止まる不具合、1 台を止めたままの up の不合格）を記録し、直した
  （Traefik を 1 台ずつ入れ替え、チャートの版に合うログの鍵、止まった台があれば up を分かるメッセージで止める）。
  詳細は `.history/2026-11-08-Traefikの更新と止まった台/` 1〜5 章。
- 別に切ったブランチ（`fix/traefik-update-and-stopped-node`）を、ユーザーの指示で #9 のブランチに取り込んで消した。
- EC2 の仕上げ（同じ変更記録の 5 章以降、結果は変更設計書 15 章）:
  - 80 番から 443 番への転送の鍵（`ports.web.http.redirections`）
  - 版上げ中の Traefik のチャートの見張り（`stages.TraefikChartWatch`）、台ごとの失敗（`ops.failures_per_segment`）
  - metrics-server 2 台（散らす、PDB）、LiteLLM の PDB 25%
  - `worker-node` は足す台に LiteLLM を載せてから止める
  - AMI の CPU の種類をインスタンスの種類から選ぶ（amd64 で全試験）
  - `./lab upgrade-ami [--measure]`（1 台ずつ作り直す。PVC とノードを消し、同じ IP で作り直して参加。途中から続けられる）
  - Zabbix に LiteLLM の指標（Pod ごとの `/metrics`、全 Pod の合計、失敗の割合、平均の待ち時間、警報 2 つ）
  - `K3S_IMAGE` を v1.37.2 に
  - AWS で見つけて直した 7 件: スナップショットを足す台で取ろうとした、版の食い違いの案内が逆、k3s の取得の一時的な失敗、
    upgrade-ami の続き（2 件）、`/metrics` が鍵を求める、踏み台のホスト鍵の取り違え
- AWS の試験（2026-11-08 20:40〜11-09 00:20）: 構築、疎通、全 7 場面の障害の試験、版上げ（パッチ・マイナー・途中で止めて再実行・
  飛ばす/下げる指示）、1 台の作り直し、upgrade-ami、Zabbix の指標、冪等性、managed の down、provided（担当部署の役で
  `docs/provider-requests.md` どおりに作った物）の up・足す台の外しと戻し・`down --all`。有料の資源の残り 0 件を API で確認。
- docs/spec.md、docs/design.md、バックログに反映。#9 の説明を最終の状態にし、ユーザーがマージした（2026-11-09 00:55）。
- 単体テスト 106 本が通る。
- 意図的に残したもの: Mac の k3d と gcp-vm での確認（EC2 の範囲外）、test-judge（審査官のキーが 12/1 まで上限）、本物の Zscaler と踏み台。

## 決定事項
- 直しは元のプルリクエスト（#9）のブランチで続ける。勝手に別のブランチを切らない（ユーザー指示 2026-11-08）。
- 試験で問題が出ても環境を消して作り直さない。その場で直して流し直し、全部通ってから落とす（費用のため。ユーザー指示 2026-11-08）。
- 見つけた不具合はバックログに回さず、同じプルリクエストで直して確かめてから報告する（「毎回残る」への指示 2026-11-08）。
- 「EC2 の完成」は不具合・試験の残りに加え、AMI のコマンド、Zabbix の LiteLLM の指標、amd64 を含む（1A）。PDB 25%（2A）、metrics-server 2 台（3A）。
- LiteLLM の `/metrics` は鍵なし。外からは Traefik が踏み台だけに絞る（6A）。
- AMI のコマンドの細目と Zabbix の指標と `K3S_IMAGE` v1.37.2 は、おすすめで進めた（「EC2 を完成させて」の指示）。
- 進捗は取り決めどおり（時計の時刻の見込み、30 分を超えない確認）、日本語で報告する（英語で報告してしまい指摘された）。
