## 概要
AWS サポートの対応で Bedrock と計算資源の制限が解け、Anthropic の利用目的フォームを送って Claude が使えるようになった。サポートケース 3 件を閉じ、実績用 ElastiCache を消した。次は EKS の構成（`LAB_TARGET=aws`）の配備。

## やったこと

### ブランチの整理（11/1）
- PR #7（`feature/aws-target`）のマージを受けて main に戻り、取り込み済みのローカルブランチ `feature/aws-target`・`feature/context-review-claude-code`・`feature/isolated-content-read` を消した。
- ユーザーが orca 側で作業ツリー 2 つ（`feature-aws-target-2`、`コンテキスト独立tool引数監査`）と `feature/aws-ec2-pair` を片付けたことを確かめ、バックログの該当 2 件を完了に移した。

### AWS の制限の解除（11/1〜11/3）
- 11/1 00:47 JST: 技術ケース 179340373000600 に AI/ML チームの担当者が付き、Bedrock の利用の申請を社内チームに回した。返答に計算資源への言及が無かったので、計算資源の上限 0 も同じ審査に入れるよう返信した（ユーザー承認の文面）。
- 11/3 18:45 JST: 「Bedrock の利用を戻した」と返答。計算資源は「別のケースで」とあったが、確かめると EC2 のオンデマンド 64・スポット 256・Fargate 64 vCPU にすでに戻っていた。
- Haiku 4.5 は Anthropic の利用目的フォームを求めた。ユーザーが外出中で、操作と送信の許可を得て、私がコンソールから送信した（IAM Identity Center のポータルに残っていたセッションで入れた。資格情報の入力なし）。15 分後に Sonnet 4.5・Haiku 4.5（東京 `jp.`）とも応答。API で読み直した登録内容は決めたとおり（利用目的の先頭に「. 」が余計に入ったが意味は同じ）。
- お礼を返信して 3 件のケースを閉じた（ユーザー承認の文面）。不要になった 16 vCPU の上限の申請も CASE_CLOSED。
- 実績用の ElastiCache `litellm-lab-activity` とサブネットグループを消した（既定 VPC は残した）。

### 予算と請求
- 11/2: 予算「My Monthly Cost Budget」（月 20 ドル）が 11/1 に 32.12 ドルで超過の通知。内訳は Business Support+ の 11 月分 29 ドル（月初に一括計上）、税 2.92 ドル、ElastiCache 0.20 ドル。トライアルの返金はまだ計上されていない。
- 予算の絞り込みを「返金とクレジット以外すべて」から「料金の種類が Usage のものだけ」に変えた（ユーザー回答 A）。11 月の実績として数えるのは 0.20 ドルになった。
- 10 月分の請求書は 510 円（3.20 ドル。ElastiCache 1.14、Business Support+ の日割り 0.95、RDS 0.35、EC2 関連 0.19、VPC 0.18、Cost Explorer の API 0.03 ほか、税 0.29）。Cost Explorer の API は 1 回 0.01 ドルかかる。

### Zscaler の扱いの調査
- `aws-ec2` / `gcp-vm` は、明示プロキシの Zscaler（`LAB_EGRESS_PROXY` と `LAB_EGRESS_CA_FILE`）の中で、構築の最初から作れる実装になっている（VM・k3s・Pod・VM 上のビルド・Mac の `./lab`）。GCP で mitmproxy を代わりに使って確認済み。AWS と本物の Zscaler では未確認。
- 透過型（Cloud Connector など、経路で送る形）だと CA が配られないが、ユーザーから「本番は明示プロキシ」と回答があり、対応は足さない。

### 許可の判定で止まったもの
- Claude Code の自動の許可判定で、予算の書き換え・ElastiCache の削除・サポートケースへの書き込みが止まった。どれもユーザーが「許可します」と書いてから実行した。私が下書きした文面の外部送信は、文面の承認を先に取ると通る。
