# 変更仕様書: 障害の試験の負荷を VPC の中（中継の VM）から送る

作成: 2026-11-05
状態: 実装済み・AWS で確認済み・docs/ に反映済み（2026-11-05）
この文書の役割: **何を満たすか（要件）と、何を決めたか（決定）**。どう作るかは `変更設計書.md`

## 0. 背景と決定事項

### 0.1 背景

`aws-ec2` の `pg-node` で、LiteLLM が ready に戻った後も約 40 秒、接続のリセットや TLS の途中切断が続いた
（`.history/2026-11-05-1台だけの部品の冗長化/変更設計書.md` 4.1 節）。試験の負荷は Mac → 踏み台の SSH の転送 → 内部 NLB を通り、
溜まった要求が一度に流れた時間帯と重なるので、転送の側の失敗と推定した。本番の利用者は VPC の中から NLB に届く。

### 0.2 決定事項（2026-11-05、ユーザーの回答）

| # | 問い | 決定 |
|---|---|---|
| 1 | 測り方 | VM 構成では、試験の負荷を VPC の中（中継の VM）から送る（1A） |
| 2 | provided の扱い | managed では中継の VM から送る。provided では今までどおり Mac から送る（踏み台に試験の道具を置く依頼を避ける）（1A） |
| 3 | 確認 | 障害の試験の全場面を、観測を付けて 1 回の配備で流す（2A） |

## 1. 要件

- R1. `LAB_TARGET=aws-ec2` / `gcp-vm` の managed で中継の VM があるとき、`test-failover` と `upgrade-k8s --measure` の負荷の要求は中継の VM から
  入口（内部ロードバランサ、`https://<LAB_HOSTNAME>`）へ送る。
- R2. 判定（回復の時間、失敗が続いた時間、監査ログの照合）は今と同じ数え方で行う。
- R3. マスターキーをコマンドの引数やファイルに残さない。
- R4. provided と Mac の環境は今までどおり Mac から送る。

## 2. 受け入れの確認

- AWS（`aws-ec2`、managed）で `test-failover` の全場面を流し、要求が中継の VM から送られ、判定と監査ログの照合が動く。
