## 0. 背景と決定事項

### 0.1 背景

2026-11-08 の `aws-ec2` の残りの試験（`.history/2026-10-31-内部LBとVM側の防御とZabbix/変更設計書.md` 15.2.4 節）で次が分かった。

- 36: 入口の Traefik の DaemonSet は、定義が変わると新しい Pod を置けず、更新が終わらない。チャートの既定の更新の仕方（先に 1 つ足し、止めるのは 0）と、
  台の 80 / 443（hostPort）の取り合いのため。k3s 1.37 はチャートが 40 → 41 に変わるので、`upgrade-k8s` で 1 台ごとに 300 秒の時間切れになった。
- 39: Traefik のチャート 41 で `logs.access` が `accessLog` に改名された（あわせて `fields.headers.defaultmode` が `defaultMode`）。
  k3s 1.37 に上げると、アクセスログが出なくなる。
- 38: 1 台を止めたまま `./lab up` を流すと、EC2 が動き出すのを 300 秒待ち、Python の例外の全文で止まる。

## 1. 要件

- R1. `aws-ec2` / `gcp-vm` で Traefik の定義が変わったとき（`./lab up` で設定を変えた、k3s の版上げでチャートが変わった）、全台の Traefik が新しい定義に
  入れ替わる。入れ替えは 1 台ずつで、同時に止まる Traefik は 1 台まで。
- R2. Traefik のアクセスログが、チャート 40（k3s 1.36）でも 41（k3s 1.37）でも出る。`upgrade-k8s` の途中と後も出る。Mac の k3d も同じ。
- R3. `aws-ec2` / `gcp-vm` の `./lab up` は、止まっている台があると、待たずに止まる。メッセージに止まっている台（ノード名と識別子）と、起こしてから
  流し直す案内を出す。managed と provided の両方。
- R4. `./lab up` を 2 回流したとき、2 回目で何も変わらない（冪等）。

## 2. 範囲

- 変えるもの: `k8s/traefik-config-vm.yaml`、Traefik の設定を当てる処理（Mac と VM の `cluster` 段階、`upgrade-k8s`）、台の状態の確かめ（`cluster` 段階）。
- 変えないもの: Mac の Traefik の更新の仕方（Mac は Deployment で hostPort を使わない）。止まった台を起こす処理は足さない（3B）。

## 3. 受け入れの確認

- 単体テスト（構築ツールとガードレール）が通る。
- AWS（`aws-ec2`）で:
  - `./lab up` の後、Traefik の DaemonSet の更新の仕方が `maxUnavailable: 1`・`maxSurge: 0`、アクセスログの引数がある。
  - 1 台を止めたまま `./lab up` を流すと、止まっている台を示すメッセージで止まる。
  - `upgrade-k8s v1.37.1+k3s1 --measure` で、Traefik が全台チャート 41 の定義に入れ替わり、アクセスログの引数がある。台ごとに Traefik の待ちの時間切れが出ない。
  - 版上げの後の `test-smoke` が通る。

### 5.2 要件

- R5. VM の構成で、入口の 80 番への要求が 443 番（https）へ転送される（チャート 39〜41）。
- R6. `upgrade-k8s` の途中でチャートが変わっても、アクセスログの指定が無い Traefik の定義が残る時間を数秒にとどめる（R2 の「途中も出る」を満たす）。
- R7. metrics-server が 2 台で、別々の台に載る。1 台を止めても CPU の値が取れ、自動の台数調整が続く。drain で 2 台が同時に追い出されない。
- R8. LiteLLM の PDB は、一度に追い出してよい数を 25%（切り上げ）にする。2〜4 台なら 1 で今と同じ、5〜8 台なら 2。
- R9. `test-failover --scenario worker-node` は、LiteLLM が載った足す台を必ず止める。載っていなければ負荷を流す前に LiteLLM を入れ替えて載せ、
  それでも載らなければ場面を流さずに分かるメッセージで止まる。
- R10. `upgrade-k8s --measure` は、要求の失敗の数と散らばった幅を台ごとにも出す。
- R11. `aws-ec2` の台の AMI は、`LAB_EC2_INSTANCE_TYPE` の CPU の種類（arm64 / amd64）に合う Ubuntu 24.04 を選ぶ。

### 5.3 受け入れの確認（AWS の `aws-ec2`、amd64（`t3.large`）、足す台 1）

- `./lab up` が通り、80 番への要求が 443 番への転送（308）を返す。metrics-server が 2 台で別々の台、LiteLLM の PDB が 25%。
- `test-smoke`、`test-failover`（全場面、`worker-node` を含む）が通る。
- `upgrade-k8s` で、パッチの更新（v1.36.5 → v1.36.6）、マイナー版の更新（v1.36.6 → v1.37.2、途中で止めてもう一度流す）が通り、台ごとの失敗が出る。
  飛ばす指示と下げる指示は分かるメッセージで止まる。上げた後の `./lab up` は版の食い違いで止まり、`K3S_IMAGE` を合わせると通る。
- チャートが変わったとき、`./lab` が数秒のうちに当て直す（`traefik_chart_changes` と DaemonSet の履歴）。
- 版上げの後も metrics-server が 2 台で、CoreDNS が 3 台。
