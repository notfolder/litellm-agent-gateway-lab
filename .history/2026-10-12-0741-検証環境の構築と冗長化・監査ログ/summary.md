# 検証環境の構築と、DB・Redis の冗長化、監査ログの実装

## 概要
LiteLLM ゲートウェイの検証環境（k3d、Gmail の MCP、ツールコール審査）を作り、PostgreSQL 3 台・Valkey と Sentinel・RustFS・監査ログと検索アプリを実装して試験を通し、main に push した。

## やったこと

- **仕様と設計（2026-10-10〜11）**: `docs/spec.md` と `docs/design.md` をヒアリングで作った（Jev の有無の切り替え、Gmail の MCP は google_workspace_mcp をクラスタ内に置く、図は Mermaid）
- **検証環境の構築（2026-10-11、`7880fa8`〜`9977e27`）**: 構築ツールを Python の `./lab` で作り直し、k3d 上に LiteLLM・PostgreSQL・Redis・Gmail の MCP・審査ガードレールを立てた。Google の SSO とユーザーごとの Gmail の MCP、ChatGPT と Jev を有効にし、Codex の MCP の起動とサインインの手順、審査官の誤ブロックを直した
- **冗長化と監査ログ（2026-10-11〜12、`222c9f8`〜`19b6919`）**: 変更仕様書と変更設計書は `.history/2026-10-11-冗長構成と監査ログ/`
  - RustFS（S3 互換のオブジェクトストレージ）、CloudNativePG の PostgreSQL 3 台（Pooler、バックアップ、任意の時点への復元）、Valkey 3 台と Sentinel 3 台
  - 監査ログ（入出力の全文を S3 に 90 日、改ざん防止）、整形の定期処理、利用料と精算と閲覧の記録を出す検索アプリ（`/lab-audit/`）
  - 試験: 障害（Pooler／直結）、復元、監査ログ 27/27、検索の速さ（合成データ 1 日 100 万件 × 7 日）、冪等性、単体、疎通。結果は今の `docs/design.md` 16.5
  - 試験で見つけて直したこと: ノード停止で全体が止まる（オペレーターを server ノードへ、LiteLLM と Pooler を散らす）、消した primary の Pod が残る（CNPG の停止の待ちを短縮）、検索アプリと RustFS と DB 移行の Job のメモリ不足、マスターキーの要求の扱いなど
- **最後に片付けたこと**: Gmail の MCP にサインインし直して監査ログの試験 27/27。Google Cloud の OAuth クライアントにリダイレクト URI `http://localhost:8080/lab-audit/auth/callback` を足し（ユーザーの許可を得てブラウザで保存）、ブラウザで検索アプリに入れることを確かめた。main を push（`9977e27..19b6919`）
- **取り込み**: 別ブランチの文脈独立のツール引数監査（PR #1、`af29f44`）と作業ルール（`f647912`）が main に入った。docs は単独で読める形に書き直され、このセッションの試験結果は spec 9.3・9.4 と design 16.5 に残っていることを確かめた
- **意図的に残したもの**: `~/.claude/estimate-log.md` に見積もりと実績の差を 1 行足した（見積もり 11.3h、実績 約 5.5h）。プロジェクトのセッションなのでコミットしていない

## 決定事項

- DB の接続は Pooler を主、直結を比較用。直結の計画的な切り替えと Pod の削除の目安は 90 秒に見直した（Pooler と、ノード停止は当初の目安のまま）
- Valkey は公式イメージと自前のマニフェスト。オブジェクトストレージは RustFS（S3 に置き換えられる形）
- 入出力の全文は S3 だけに 90 日（本番は COMPLIANCE のロック）。日次の集計・閲覧の記録・管理操作の記録は 13 か月。日付と月は日本時間
- 利用料は単価表の概算（A）と実費の按分（B、A の額の割合で配る）。審査の利用料はツールコールを出した利用者に付ける。請求の単位は共有のみで、単位ごとの通貨を円に換算して精算する
- `disable_spend_logs` を受け入れる（LiteLLM の Usage と Logs の画面は使わず、検索アプリを使う）。S3 の障害中に Pod が止まったときの退避分の欠けも受け入れる
- ログインと同意のボタンはユーザーが押す。今回の「Finish connecting」と Google Cloud の保存は、その場で許可を得て行った（許可はその回限り）
- push は確認を取ってから行う
