- 送信そのものをゲートウェイの出口のプロキシに通して実際に送られる中身を検査する方式。最も汎用だが別の部品で規模が大きいので見送り。層の整理: 層 1 ゲートウェイ＝LLM の行動、層 2 エージェントのサンドボックス、層 3 出口のプロキシ（追加 2026-10-17）
- Claude Code でスクリプト経由の社内連携を通す方法。環境変数の値を出力する読み取りをモデル自身が拒み、分類器も止める。宛先を設定ファイルに置く形や Claude Code 側の許可設定を検討（試験結果は design 16.6）（追加 2026-10-17）
- 座標だけのクリック（引数に手掛かり無し）は Jev の一次判定が閾値 0.2 の際（0.19〜0.28）で、二次判定に届かず通る回がありうる。「今のまま」と決めた。閾値は評価セットで待ち時間の増え方を測ってから見直す（追加 2026-10-18）
- Claude Code に文脈あり審査を掛けたときの、自分のリポジトリへの push・PR 作成の誤ブロック（許可の言葉が無いと止まる）。実運用で不便なら、審査官に許可リストの宛先と作業中のリポジトリの remote を「許可なしで送ってよい宛先」として渡す案。「許可の言葉は今のまま」を選んだ（追加 2026-10-18）
- 切れた読み取りで止めた後、大きい送信が分割を求められるのが実運用で不便なら、会話の末尾に連続する読み取りを合算する方式（B 案）で容量を戻す（追加 2026-10-18）
