# 変更仕様書: 入口の Traefik に CPU とメモリの要求を付け、生存確認を緩める

作成: 2026-11-05
状態: 実装済み・AWS で確認済み（変更設計書 3 章）
この文書の役割: **何を満たすか（要件）と、何を決めたか（決定）**。どう作るかは `変更設計書.md`

## 0. 背景と決定事項

### 0.1 背景

`aws-ec2` の障害の試験で台を 1 台止めると、止めていない台の Traefik が生存確認に応答できずに再起動させられ、LiteLLM が戻った後も
失敗が続いた（pg-node 175.1 秒、valkey-node 159.7 秒。`.history/2026-11-05-障害試験の負荷をVPCの中から/変更設計書.md` 4 章）。
k3s に同梱の Traefik は CPU とメモリの要求を持たない（BestEffort）。

### 0.2 決定事項（2026-11-05、ユーザーの回答）

| # | 問い | 決定 |
|---|---|---|
| 1 | 要求 | VM 構成の Traefik に CPU 100m・メモリ 64Mi の要求を付ける（1A） |
| 2 | 生存確認 | 時間切れ 5 秒、6 回失敗で再起動（約 1 分応答しなければ再起動）に緩める（2B） |
| 3 | 確認 | AWS で全 6 場面を観測付きの台本で 1 回流し、台ごとの CPU の時系列も記録する（3A） |

## 1. 要件

- R1. `aws-ec2` / `gcp-vm` の Traefik の Pod が CPU 100m・メモリ 64Mi の要求を持つ。
- R2. Traefik の生存確認は時間切れ 5 秒、6 回失敗で再起動する。
- R3. 台を 1 台止めた場面で、止めていない台の Traefik が再起動させられない。

## 2. 範囲

- 対象: VM 構成（`k8s/traefik-config-vm.yaml`）。Mac の k3d（`k8s/traefik-config.yaml`）と EKS 版は変えない。
