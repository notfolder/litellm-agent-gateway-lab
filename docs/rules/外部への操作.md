# 外部への操作

## Google などのログイン・同意のボタンはユーザーが押す

- 検証環境の構築（2026-10-11〜12）で、Google の SSO、Gmail の MCP のサインイン、Google Cloud のコンソールの操作が何度も必要になった
- アカウントの選択、権限の許可、LiteLLM の管理画面のログインはユーザーが押した。私がブラウザで押したのは、ユーザーがその回に許可したものだけ（Gmail の MCP の「Finish connecting」、Google Cloud の OAuth クライアントへのリダイレクト URI の追加と保存）
- 許可はその回限り。前に許可されたことを理由に、次の回に黙って押さない
- DB を作り直すと、Gmail の MCP のサインインと、ブラウザに残った管理画面のログインが無効になる。サインインの URL が 401（Invalid proxy server token）を返したら、管理画面からログアウトして、ユーザーにログインし直してもらう

## push は確認を取ってから行う

- 2026-10-12、「実装して、試験が通ったら … コミットして」の指示では push しなかった。変更仕様書で push を「まとめて確認を取ってから」としていたため
- コミットの後に、push してよいかを確認事項で聞き、「1 A push してください」と答えをもらってから push した

## `.history/` はすべてコミットする

- 2026-10-12、引き継ぎの準備の後に「.historyの内容もコミットしてください」と指示された。それまでは `.gitignore` で、変更仕様書と変更設計書以外の `.history/`（summary.md、session.md、BACKLOG.md）を公開しないことにしていた
- リポジトリは公開しているので、session.md の全記録も公開されることを説明し、ユーザーが了承した（案 A）。`.gitignore` から `.history` の除外を消した
- コミットの前に、実在のメールアドレスを `<ユーザー1のメール>`、`<ユーザー2のメール>` に置き換え、キー・トークン・シークレット・秘密鍵の形の文字列が無いことを grep で確かめる
- スキル `session-handover` の注意書き（`.history/` は非公開のリポジトリに置く）とは違う扱いになる。このリポジトリではこちらに従う
